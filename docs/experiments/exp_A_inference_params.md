# 实验 A：推理参数（temperature / num_ctx）对速度与输出稳定性的影响

## 1. 业务问题

信贷分析场景中，模型的推理参数直接影响回答的**稳定性**（同一输入是否给出一致结论）和**响应速度**。风险因素提取、结构化输出等任务需要可复现；而报告措辞可以适当自然多变。

## 2. 技术问题

- `temperature` 如何影响生成随机性与稳定性？
- `num_ctx`（上下文窗口）如何影响推理耗时与内存？

## 3. 假设

- 低 temperature 输出更稳定（几乎确定），高 temperature 措辞更多变。
- 更大 num_ctx 会增加单次推理耗时（KV cache 更大）。

## 4. 实验设计

- 模型：`qwen3:30b`（Qwen3-30B-A3B Instruct-2507，Q4_K_M），本地 Ollama
- 温度实验：固定 `num_ctx=4096`，同一问题在 `temperature=0.1 / 0.5` 各重复 3 次
- 上下文实验：固定 `temperature=0.1`，同一问题在 `num_ctx=4096/8192/16384` 各测一次（每个 ctx 先预热以排除 KV cache 重建耗时）
- 统一预热，`keep_alive=10m` 保持模型常驻

## 5. 评价指标

推理耗时（`total_duration - load_duration`）、输出 token 数（`eval_count`）、输出字数、输出文本一致性。

## 6. 实际结果

### 温度实验（Q：用一句话解释什么是信用风险；num_ctx=4096）

| temp | rep | 推理耗时(s) | 输出 tok | 输出字数 |
|---|---:|---:|---:|
| 0.1 | 0 | 0.304 | 25 | 47 |
| 0.1 | 1 | 0.260 | 22 | 43 |
| 0.1 | 2 | 0.262 | 22 | 43 |
| 0.5 | 0 | 0.307 | 25 | 48 |
| 0.5 | 1 | 0.309 | 26 | 47 |
| 0.5 | 2 | 0.308 | 26 | 48 |

观察：temp=0.1 的 3 次输出中 rep1 与 rep2 **逐字相同**；temp=0.5 的 3 次在措辞上有轻微差异（如「偿还本金和利息义务」vs「按约定履行还款或支付义务」），但语义一致。耗时差异在噪声范围内（0.26~0.31s）。

### 上下文实验（Q：偿债能力风险判断；temp=0.1）

| num_ctx | 推理耗时(s) | 输出 tok | 每 token(ms) |
|---|---:|---:|---:|
| 4096 | 4.238 | 358 | 11.8 |
| 8192 | 4.489 | 364 | 12.3 |
| 16384 | 5.797 | 472 | 12.3 |

观察：num_ctx=16384 的总耗时明显更高（5.8s vs 4.2s），但**每 token 吞吐基本持平（~12ms/tok）**——总耗时增加主要来自该次输出更长的回答（472 tok），而非 num_ctx 本身拖慢单 token 速度。

## 7. 失败案例与局限

本次未观察到明显的事实性失败（所有回答均正确给出「信用风险定义」/「高风险」结论）。但存在**方法论局限**，需诚实记录：

1. **输出长度与 num_ctx 混淆**：num_ctx 对比中，模型在更大 ctx 下恰好写了更长的回答，导致「总耗时」不能干净地归因于 num_ctx。后续应改为固定 `max_tokens` 或比较「每 token 耗时」。
2. **样本量小**：温度仅各重复 3 次，不足以量化方差；稳定性结论只能定性。
3. **未直接测内存**：num_ctx 的主要代价是 KV cache 内存，本次未用工具实测（48GB 内存下 16K 无压力）。

## 8. 结论

- 假设 1（温度影响稳定性）**成立**：temp=0.1 更稳定（出现逐字一致），temp=0.5 措辞有轻微变化，但二者耗时无明显差异。
- 假设 2（num_ctx 拖慢推理）**部分成立**：总耗时随 num_ctx 上升，但主要是输出变长导致；每 token 吞吐 ~12ms 基本不变。真实成本在于内存（KV cache），短输入场景下 4K→16K 对速度影响有限。

## 9. 技术决策

- **默认 temperature=0.1**：用于风险因素提取、结构化输出、数值相关任务，保证可复现。
- **报告生成可适度放宽到 0.5**：在措辞自然度和一致性之间取平衡。
- **num_ctx 按任务长度配置**：短问答用 4096 足够；处理长文档/RAG 上下文时再上调，不必默认拉到 16K（省内存）。

## 10. 下一步

- 用固定 `max_tokens` 重跑 num_ctx 对比，消除输出长度混淆。
- 若要严谨量化稳定性，可增加重复次数（≥10）并统计文本编辑距离。
- 补充量化对比实验（实验 B，可选）：Q4 vs Q8 的精度/速度差异。
