# 实验 A（v2）：推理参数对速度、稳定性、结构化输出与资源的影响

> v2 在 v1（只测 temperature / num_ctx）基础上扩展为 7 组单变量对照，并修正 v1 报告自指出的两个方法缺陷：① 温度稳定性重复次数 3→10、用量化指标而非定性描述；② num_ctx 对比固定 `num_predict=256`，消除「输出变长」对总耗时的混淆。新增 top_p / top_k / max_tokens / seed / 结构化 JSON / 运行时显存 六个维度。

## 1. 业务问题

信贷分析场景里，推理参数直接决定回答的**稳定性**（同一输入是否给出一致结论）、**响应速度**、**结构化输出可靠度**和**内存成本**。风险因素提取、结构化输出需要可复现；报告措辞可适度自然多变；而 num_ctx 越大 KV cache 内存越高。

## 2. 技术问题

- `temperature`、`top_p`、`top_k` 如何影响生成随机性与稳定性？
- `num_ctx` 对吞吐与显存的实际影响？
- `num_predict`（Ollama 的 max_tokens）截断是否伤害关键结论？
- `seed` 能否让采样输出可复现？

## 3. 假设

- H1：低 temperature 输出更稳定，高 temperature 措辞更多变，吞吐无明显差异。
- H2：固定输出长度后，num_ctx 4K→16K 对单 token 吞吐影响很小，主要成本在 KV cache 内存（线性增长）。
- H3：top_p 越小多样性越低；top_k 有类似收紧作用。
- H4：`num_predict` 过小会截断关键结论。
- H5：固定 seed 可复现输出。

## 4. 实验设计

- 模型：`qwen3:30b`（Qwen3-30B-A3B Instruct-2507，Q4_K_M），本地 Ollama，`keep_alive=10m` 常驻
- 原则：**每组只改变一个变量**，其余固定为默认（temperature=0.1, num_ctx=4096, num_predict=None）；统一预热
- 固定任务集（3 个问题全实验复用）：
  - `Q_DEF`：用一句话解释什么是信用风险。
  - `Q_DTI`：某客户月收入8000元，已有每月5000元负债，评估其偿债能力风险属于高、中还是低水平？
  - `Q_JSON`：从客户信息抽取 `monthly_income/monthly_debt/overdue_6m/risk_level` 并只输出 JSON

| 组 | 变量 | 取值 | 任务 | 重复 |
|---|---|---|---|---|
| R1 温度 | temperature | 0.1 / 0.5 | Q_DEF | 各 10 |
| R2 上下文 | num_ctx | 4096 / 8192 / 16384（固定 num_predict=256） | Q_DTI | 各 1（预热后计时） |
| R3 top_p | top_p | 0.5 / 0.9 / 1.0（temp=0.5） | Q_DEF | 各 5 |
| R4 top_k | top_k | 10 / 40 / 100（temp=0.5） | Q_DEF | 各 5 |
| R5 生成长度 | num_predict | 64 / 256 / 1024 | Q_DTI | 各 1 |
| R6 随机种子 | seed | 42 / None（temp=0.5） | Q_DEF | 各 3 |
| R7 结构化 | temperature | 0.1 / 0.5 | Q_JSON | 各 5 |

## 5. 评价指标

推理耗时（`total_duration - load_duration`）、吞吐（`eval_count / inference_s`）、输出 token 数、**归一化编辑距离**（0=完全相同，1=完全不同，两两样本均值）、完全一致对数、JSON 可解析率 / 字段完整率 / 数值一致率、截断标志、**运行时显存**（`/api/ps` 的 `size_vram`，含权重 + KV cache）。

## 6. 实际结果

### R1 温度实验（Q_DEF；10 次重复）

| temp | 平均编辑距离 | 唯一输出 | 完全一致(两两) | 平均吞吐 |
|---|---:|---:|---:|---:|
| 0.1 | 0.026 | 3/10 | 28/45 | 82.7 tok/s |
| 0.5 | 0.118 | 9/10 | 1/45 | 83.9 tok/s |

temp=0.1 下 10 次输出几乎一致（45 对两两比较中 28 对逐字相同，编辑距离 0.026）；temp=0.5 下仅 1 对相同、9/10 唯一输出。吞吐无差异。

### R2 上下文实验（Q_DTI；固定 num_predict=256，消除输出长度混淆）

| num_ctx | 推理耗时(s) | 输出 tok | 吞吐 | 显存 size_vram(MB) |
|---|---:|---:|---:|---:|
| 4096 | 3.048 | 256 | 84.0 | 17820.6 |
| 8192 | 3.035 | 256 | 84.3 | 18036.6 |
| 16384 | 3.117 | 256 | 82.1 | 18468.6 |

固定输出长度后，4K→16K 吞吐基本持平（84→82 tok/s，~2% 噪声）。**成本在内存**：显存随 num_ctx 近似线性增长（4096→8192 +216MB，8192→16384 +432MB，约 54MB/1K ctx）。

### R3 top_p 实验（temp=0.5；5 次重复）

| top_p | 平均编辑距离 | 唯一输出 |
|---|---:|---:|
| 0.5 | 0.067 | 2/5 |
| 0.9 | 0.131 | 4/5 |
| 1.0 | 0.126 | 5/5 |

top_p=0.5 明显收窄多样性；0.9 与 1.0 差异不大（1.0 完全不截断候选，唯一输出最多）。

### R4 top_k 实验（temp=0.5；5 次重复）

| top_k | 平均编辑距离 | 唯一输出 |
|---|---:|---:|
| 10 | 0.139 | 4/5 |
| 40 | 0.233 | 5/5 |
| 100 | 0.106 | 4/5 |

**非单调**（40 最多样、100 反而最少样）。短事实句 + 样本量 5 下噪声大，单凭此实验不足以支撑 top_k 的取舍结论。

### R5 生成长度实验（num_predict）

| num_predict | 推理耗时(s) | 输出 tok | 截断 | 结论完整(含「高风险/高水平」) |
|---|---:|---:|---|---|
| 64 | 0.868 | 64 | 是 | 否 |
| 256 | 3.099 | 256 | 是 | 是 |
| 1024 | 4.662 | 390 | 否 | 是 |

num_predict=64 太短，DTI 结论被截断；256 已覆盖关键结论；该任务自然输出约 390 tok。延迟随 num_predict 近似线性。

### R6 随机种子实验（temp=0.5；3 次重复）

| seed | 3 次输出完全一致 |
|---|---|
| 42 | ✅ 是 |
| None | ❌ 否 |

固定 seed 可复现采样输出，可用于 Golden Set 重跑时的确定性对比。

### R7 结构化 JSON（5 次重复）

| temp | 可解析 | 字段完整 | 数值一致 |
|---|---:|---:|---:|
| 0.1 | 5/5 | 5/5 | 5/5 |
| 0.5 | 5/5 | 5/5 | 5/5 |

在明确 schema + 「只输出 JSON」的提示下，0.1 和 0.5 均稳定产出合法 JSON 且数值正确；10 次输出甚至逐字相同（`risk_level` 一致为 `medium`）。格式稳定性很好，但 `risk_level` 的判断值可能偏保守，见失败案例 1。

## 7. 失败案例与局限

1. **结构化判断与直接判断不一致**：Q_JSON 抽取中，模型对「月收入8000/月负债5000/逾期2次」10 次全部给出 `risk_level="medium"`；但同一模型在 Q_DTI 直接判断（同一 DTI=62.5%）时结论是「高风险」。格式约束/任务措辞会改变模型的语义判断——印证「JSON 可解析不代表内容正确」，`risk_level` 这类衍生字段必须由规则或模型服务确定，LLM 只负责抽取与解释。
2. **top_k 非单调**：短事实性回答的多样性天然受限，top_k 效应被噪声淹没；要下结论需更大样本或更长/更开放的任务。
3. **显存测量口径**：`size_vram` 是「权重 + KV cache」总量，权重 ~17.4GB 占大头，KV 增量是差值（约 54MB/1K ctx），非直接测得的纯 KV 分配。
4. **结论完整性用关键词粗判**：「高风险/高水平」是否出现，未做语义级判定；更严谨应固定 Golden Set 做人工/LLM 评分。
5. 本次所有回答均给出正确风险结论，未观察到事实性失败；这本身也是局限——未构造会诱导错误的输入（那是实验 D/R 的范围）。

## 8. 结论

- H1 **成立**：temp=0.1 稳定性显著更好（编辑距离 0.026 vs 0.118），吞吐无差异。
- H2 **成立**：固定输出长度后 4K→16K 吞吐几乎不变，成本在内存线性增长。
- H3 **部分成立**：top_p=0.5 收紧多样性明显；top_k 在本任务下非单调，证据不足。
- H4 **成立**：num_predict=64 截断关键结论，256 已足够。
- H5 **成立**：固定 seed 可复现输出。

## 9. 技术决策

- **默认 temperature=0.1**：风险因素提取、结构化输出、数值相关任务，保证可复现。
- **报告生成可放宽到 0.5**：编辑距离 0.118，措辞自然度提升且语义稳定。
- **num_ctx 按任务长度配置**：短问答 4096 足够；长文档/RAG 再上调，注意 KV cache ~54MB/1K。
- **评测用固定 seed**：Golden Set 重跑时保证可复现。
- **top_p 可作额外收紧手段**（0.5）；top_k 暂不作为默认调优项。
- **num_predict 设下限 256**：避免截断风险结论。
- **风险等级由规则/模型服务确定，LLM 不自行判定**：结构化任务里 LLM 对同一客户可能给出与直接判断不一致的 `risk_level`（见失败案例 1），等级判定必须走确定性逻辑。

## 10. 下一步

- 结构化任务补充「缺失字段/冲突输入」的边界测试（实验 D）。
- top_k 用更长、更开放的任务重新验证。
- 用 Golden Set 对 temp=0.1 vs 0.5 做人工/LLM 质量评分，而不只测编辑距离。
